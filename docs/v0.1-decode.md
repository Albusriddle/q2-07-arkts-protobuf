# V0.1 解码切片：生成字段表 + NAPI `decodeUser`

日期：2026-10-29 ｜ 分支：`feature/v0.1-decode` ｜ 基线：`484eeb9`（V0）
范围：**单条 `q207.demo.User` 的真实解码入口**；不包含 tape/P4/批量/设备运行/性能结论。

## 0. 一句话

V0.1 把 V0 的 `ping`/`add` 桥接扩展为 `decodeUser(Uint8Array): DecodedUser`：
字段号与 wire type 从 `proto/example.proto` 生成，POD → 对象视图在 host 上可测；
NAPI 层只做机械映射。**HAP 已编译通过，但 `decodeUser` 没有在设备上执行过。**

## 3. 对象契约（与 norm-v1 / protobufjs 7.6.5 对齐）

```json
{
  "id": "9007199254740993",
  "name": "alice",
  "tags": ["a", "b"],
  "profile": { "city": "X", "age": 3 },
  "email": "e@x",
  "level": 7,
  "scores": { "k1": 1, "k2": 2 }
}
```

- `id` 是十进制字符串（int64 不丢精度）。
- `name`、`tags`、`scores` 恒存在；`profile` 缺失时为 `null`。
- `email`/`phone` 按 `contact_bits`（keep-all）输出，两者可同时存在。
- `level` 仅 `has_level` 时出现；显式 0 保留。
- `scores` 重复 key last-wins；整数样式 key 按 JS 顺序。
- 不输出 `unknown_fields`、`oneof_case`、`contact_bits` 等内部字段。

## 4. 已知限制

1. **未设备执行**：没有板/UDID，`decodeUser` 只在 host 侧验证对象模型，NAPI 绑定只证明编译/链接。
2. **app 不再独立构建**：app CMake 引用 `<repo>/src/host/**`；必须从 monorepo 根目录构建 HAP。CMake 会在缺少 `src/host` 时 `FATAL_ERROR`。
3. **不是完整 codegen**：只生成字段号/wire type；POD struct、decoder、ArkTS 类型仍是手写。schema 的字段集合/类型变化仍可能漏改。
4. **不包含 `decodeMany`/tape/P4/性能**；`decodeUser` 是 API 兼容里程碑，不是热路径性能路径。
5. HAP 仍是 unsigned 或本地自签；signed `installable=false`。
