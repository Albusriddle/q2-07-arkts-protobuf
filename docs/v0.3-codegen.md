# V0.3：Schema IR + generated POD + generated ArkTS types

日期：2026-10-30 ｜ 分支：`feature/v0.3-schema-pod` ｜ 基线：`main` `0c03fb3`（V0.2 + Apache-2.0）
范围：**把 POD/字段/ArkTS 类型变成 generated code**；decoder、NAPI、tape 行为不变，不做设备运行。

## 0. 结论

V0.3 把 `proto/example.proto` 变成单一事实源：

- 字段号/wire type：`q207_demo_fields.h`
- POD struct：`q207_demo_pod.h`
- schema IR：`q207_demo_schema.json` + `q207_demo_schema.h`
- ArkTS 类型：`app/entry/src/main/ets/types/libentry/index.d.ts`

`src/host/decoder/pod.h` 现在只是薄 include，不再手写 struct/字段表。
**V0.3 时 decoder 仍是手写**；V0.4 已把 parser body 生成到 `generated/q207_demo_decoder.inc`，见 `docs/v0.4-decoder.md`。

## 1. 生成物

| 文件 | 内容 |
|---|---|
| `src/host/decoder/generated/q207_demo_fields.h` | `q207::pod::f` 字段号、wire type、max field、static_assert |
| `src/host/decoder/generated/q207_demo_pod.h` | `MapEntry/Profile/User/UserBatch`，含 presence/oneof/optional 语义 |
| `src/host/decoder/generated/q207_demo_schema.json` | 机器可读 IR（package、messages、field type/label/oneof/map/wire） |
| `src/host/decoder/generated/q207_demo_schema.h` | C++ schema metadata（`FieldInfo`/`MessageInfo`） |
| `app/entry/src/main/ets/types/libentry/index.d.ts` | `DecodedProfile/DecodedUser/DecodedBatch` + API 声明 |

`pod.h` 只做：

```cpp
#include "generated/q207_demo_fields.h"
#include "generated/q207_demo_pod.h"
#include "generated/q207_demo_schema.h"
```

## 2. 兼容性与回归

- 保持 `pod::f::*`、`pod::User`/`Profile`/`UserBatch` 字段名与类型不变；
- `present()/mark()/clear()` 语义保持不变；
- `decode_user.cpp`、`object_model`、tape、NAPI 均修改 include 以外的逻辑；
- host 测试仍为 **464 assertions / 0 failed**，38/38 golden，25/25 object graph，22/22 byte-identical；
- HAP 构建、test HAP 构建、inspect 脚本通过；
- 没有设备/性能 claim。

## 4. 已知限制

1. **不是通用 codegen**：parser 只覆盖当前 proto3 子集（message/repeated/optional/oneof/map）；嵌套 message/enum/reserved 等显式失败。
2. **decoder 仍手写**：本阶段只生成 POD/字段/schema/types；oneof/map/presence 的解析逻辑仍在 `decode_user.cpp`。
3. **生成器模板针对当前 schema**：`Profile/User/UserBatch` 的结构模板在 generator 中固定；新增 schema 需要扩展模板。
4. **未设备运行**：`decodeUser/decodeMany` 的 NAPI 绑定仍只编译，`device_run=false`。
