# V0.4：从 schema IR 生成 decoder

日期：2026-10-30 ｜ 分支：`feature/v0.4-generated-decoder` ｜ 基线：`main` `ea66b6e`（V0.3）
范围：把 `decode_user.cpp` 的字段分发改为 generated include；object model / NAPI / tape 行为不变，不做设备运行。

## 0. 结论

V0.4 把 `decode_user.cpp` 的解析主体移到生成的
`src/host/decoder/generated/q207_demo_decoder.inc`：

- `parse_profile`
- `parse_map_entry`
- `parse_user_body`
- `parse_user_batch`

`decode_user.cpp` 只保留：
- 生成的 wire-type static_assert；
- `mismatch()`（strict/compat 的 wire-type 策略）；
- `user()` / `user_batch()` 的 size/clear/Reader/final-stats 外壳；
- `#include "generated/q207_demo_decoder.inc"`。

**行为不变**：468 assertions、38/38 golden、25/25 object graph、22/22 bytes 全部通过；NAPI/object model 未改。

## 1. 生成了什么

`scripts/gen_fields.py` 现在生成 **6 个文件**：

| 文件 | 内容 |
|---|---|
| `generated/q207_demo_fields.h` | 字段号、wire type、max field、static_assert |
| `generated/q207_demo_pod.h` | `MapEntry/Profile/User/UserBatch` |
| `generated/q207_demo_schema.json` | schema IR |
| `generated/q207_demo_schema.h` | C++ schema metadata |
| `generated/q207_demo_decoder.inc` | **V0.4 新增：parser 主体** |
| `app/.../types/libentry/index.d.ts` | ArkTS 类型 |

生成 include 只包含函数定义，必须 include 在 `q207::decode` 的匿名命名空间内；
它依赖 `mismatch`/`Reader`/`f` 等已有符号。

## 2. 兼容性

保持：

- `decode_user.h` API 不变；
- `pod::User`/`Profile`/`UserBatch` 结构不变；
- oneof `contact_bits`/`oneof_case`、optional `has_level`、map last-wins、危险 key 规则不变；
- error code / offset / object/field 计数顺序不变；
- NAPI `decodeUser/decodeMany`、object model、tape 不变。

## 5. 已知限制

1. **decoder 生成模板只适配当前 example schema**：`Profile/User/UserBatch` 结构和 `map<string,int32>` 是模板化假设；不是通用 protobuf 编译器。
2. **仍未设备运行**：NAPI 绑定/句柄 scope 只编译，`device_run=false`。
3. **未生成 ArkTS/NAPI 的其他类型**：仅 `DecodedProfile/DecodedUser/DecodedBatch`。
4. **未做 P4/tape**。
